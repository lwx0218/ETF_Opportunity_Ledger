## 实现中的决定（schema 没写到的细节）

1. **等权文件缺失即停**：台账已有卡片、但等权文件不存在或起点晚于最早的卡片时，当天一行不动、退出码 3、不记为已处理。否则等权基准会凭空按 0 计进冻结的出场记录。等权点位的起点是正式台账第一次运行的那天。
2. **`bench.csv` 加 `hs300_open` 列**（P2 输出）：回放也能用开盘到开盘；V1 只读 `hs300`，不受影响。
3. **旧库拒绝打开**：`ledger_meta.schema = v1.1`；之前建的库（P3 / P5 的回放库）先查版本再建表，拒绝且不改一个字节。正式台账按 A7 还没启用，所以不写迁移脚本。
4. **回放的 `--calendar`** 只影响评分截止；面板的月末在建面板时已由数据包里的日历定好。

| # | 发现 | 处理 |
|---|---|---|
| 1 | 存储层允许「事件卡 + 未检索」不带 agent 分封存；恐慌卡写成「有证据」也能入库 | cards 加 CHECK：形态突破 / 恐慌下轨 = 未检索，事件驱动 = 已检索* |
| 2 | P3 起的老问题：未封存的卡不进分母，可以先插一批、过后只封存赢家并倒填进场 | 封存触发器要求数据库时钟等于卡片 `recorded_at`（= 同一事务）且未过 `owner_score_deadline` |
| 3 | 按日历取下一交易日后，春节前一天的截止可达 11 天，被「≤ 10 天」CHECK 拒掉 | 上限放宽到 14 天并注明依据；加长假截止测试 |
| 4 | 事件草稿预期用 `int()` / `float()` 强转：`"二十"` 使整份草稿崩溃，`20.7` 被静默截成 20 | 逐条严格校验（正整数天数、有限数目标，拒绝字符串 / 布尔 / 小数天数），草稿非对象或文件非 JSON 也只报告不崩溃 |
| 5 | 等权文件只查了起点：末尾丢行、换成别的面板算的文件都不会被拦 | 每天先核对：每张卡 `close_date` 的点位等于冻结的 `cf_ew_level`；文件最后一条不早于上一交易日；CLI 拒绝「新库 + 旧等权文件」 |
| 6 | 交易日历只读第一列不校验：原样导出的非交易日、中间缺一段都会误判月末 | 文件在但一行多列、含周末、间隔 > 14 天、没有日期时报错（`build` 与 `daily` 都拒绝），没有文件才退回工作日规则 |
| 7 | 截断测试没覆盖 `bench_open` | 开盘到开盘的用例加上逐日截断（含开盘价）并比对全表与等权文件 |
| 8 | 恐慌规则配错时被静默关闭 | `load_rule_config` 收集「请求启用但被拒」的原因，CLI 打到 stderr 并写进报告 |
