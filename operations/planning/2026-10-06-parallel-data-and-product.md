## 数据线：先取得真实样本，再扩展历史

允许调查和登记新的公开数据来源，不局限于当前失败的接口。优先指数公司、交易所、基金公司及可核对身份的行情提供方；付费或需要新凭据的来源仅记录条件，不购买、不绕过访问限制。

每个候选路径保存完整 URL/参数、获取时刻、状态、原响应及哈希，核对代码与名称、币种、价格/全收益/复权语义、日期端点、重复/缺日和 OHLC 原字段。具备条件时用独立来源同日交叉核对，并查早期与近期两个窗口；交叉核对缺少的项目明确写出。网页有数字、HTTP 200 或短窗成功都不等于全历史合格。

H00300 收盘基准保留。研究候选不能拼接价格指数 OHL 与全收益 close，不能用 close 填补 OHL，也不能把 raw/qfq 冒充 hfq。本轮优先寻找原研究定义所需的真实数据；价格版本等候选可以独立保全和核验，但本计划不自动更换正式研究序列、不缩减样本池。序列选择与纳入清单在正式研究前由编排方基于数据证据单独冻结。

验证交付包括取数方法、小样检查结果、依赖/访问条件、允许回填范围及剩余风险。Pi 仅对明确通过的路径扩展历史，并再次检查分段边界、日期覆盖与历史保全；全量失败不能用局部成功冒充完成。不同路由不可直接覆盖旧序列，来源切换须按现有存储合同实施。

## Codex 首包：可运行的前向机会台账

### 目标与改动面

首包优先交付可见产品。复用 `src/ledger/`、`src/jobs/`、`src/indicators/` 和既有研究模块，新增薄 Python API 与前端；技术栈由 Codex 选择项目内最小可靠实现。部署说明和依赖落在本仓库，不引入其他项目为运行依赖。

1. 首页呈现左侧“过去/出场后跟踪”、中间“当下/持有”、右侧“未来/候选”，能够查看已结和作废记录。先让用户读懂当前判断与变化，再展示数值；不能漏掉作废分母。
2. 同页详情回答：当时为何关注、用什么证据、承诺如何验证、什么条件失效、现在发生了什么、下一观察点是什么。展示冻结预期、来源时点、每日轨迹、R 与出场后跟踪；不凭空生成证据或收益结论。
3. 演示中提供 Owner 独立评分、候选作废、手动/论点作废出场信号。走现有领域方法与时限；提交出场信号不等于立即成交，成交由既有每日流程推进。用户不能修改冻结判断或手工改行情。
4. 接入已有摘要、规则状态和数据可用性；研究未完成如实显示。没有真实卡片时给明确空态，不把 2026-09-14 原型数字当实时结果。样本不足时不画出暗示有效性的校准结论。

### 数据模式与边界

- 默认隔离演示模式：用 `Ledger` 正规方法和 replay 时钟生成候选、持有、跟踪、已结、作废样例，支持可复现推进/重置；样例不写 `data/ledger.sqlite` 或 `data/market.sqlite`。页面持续注明“演示数据”及演示截至时间。
- 正式数据模式首包只读：正式库缺失时不自动建库；使用真正的 SQLite 只读连接。`Ledger(...)` 构造函数会写 schema 与来源记录，不能拿它当只读 reader。接口不接受任意数据库路径。
- 双盲由后端保证：Owner 待评分窗口内的接口、详情、摘要和导出均不泄露 agent 分数及理由；不能仅在页面隐藏，不能直接序列化含 `agent_strength` 的全部 `card_status` 列。
- 演示写操作只访问演示库；演示配置、时钟和数据不能进入正式入口。API 默认本机预览，服务器部署由 Pi 另行执行。

### 设计与验收

遵循 intake §8 与 `docs/design/teardown-design-rules-v3.md`、tokens：深色优先，同时验浅色；背景与留白建立层次、发丝线分隔、Geist 字体、单一强调色，不做阴影卡片套卡片。`prototypes/` 仅作方向参考，交付必须连接实际 API。

浏览器验收至少覆盖：打开三态首页 → 查看冻结详情 → 独立评分 → 记录作废或出场信号 → 推进演示到下一状态 → 查看历史与分母。测试针对实际风险：冻结字段拒改、重复/过期评分拒绝、非法信号拒绝、agent 评分不泄露、演示/正式隔离、无正式库启动不建库、幂等。启动、预览和测试前后正式库哈希不变。

交付可打开的实际预览或服务器可复现启动方式、深浅两版截图及简短操作路径；不能仅交静态 HTML 或未启动的源码。独立 reviewer 与 Ponytail 按既有合同执行，通过后按 Owner 已有授权推送、合并，报告提交与验证结果。
