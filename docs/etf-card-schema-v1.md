> 面板上的每一张卡片就是台账里的一条记录。卡片不是展示层，是**数据结构本身**；UI 只是它的呈现。
> 这份文档定死：创建时锁什么、每天追加什么、出场时写什么、怎么机械打分、什么时候允许改规则。

## 0. 为什么要锁

前向记录只解决"证据可得性"（你不可能事后翻出当时没看到的新闻），不解决**选择问题**——如果结果出来之后再挑哪几条信息"解释"了它，那还是用结果做筛选。
唯一的堵法：**在结果出现之前，把预测和评分规则一起写死**。卡片创建的那一刻锁住预期、失效位和判定阈值，之后只允许追加观测，不允许修改预测。这样卡片滑到左边时，打分是机械的，没有解释空间。

## 1. 生命周期

```
候选 ──进场──▶ 当下 ──出场──▶ 过去 ──跟踪期满──▶ 已结（最终评分）
  │                                    
  └──未进场而失效──▶ 作废（仍然入库，仍然计入统计）
```

关键：**作废的卡片必须留在库里并计入分母**。只统计进场了的卡片，等于用结果筛样本。

## 2. 字段

### 2.1 创建时锁死（write-once，此后任何修改都视为新建一张卡）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `T-2026-001`，全局唯一，不复用 |
| `created_at` | datetime | 精确到分钟；必须标注对应哪个交易日收盘 |
| `container` | string | 容器名（如 半导体） |
| `instrument` | string | 执行标的代码 + 名称；研究用指数代码另记 |
| `trigger_type` | enum | `形态突破` / `恐慌下轨` / `事件驱动` |
| `state_at_entry` | enum | 形态状态：启动 / 回踩 / 平台突破 / 超跌反弹 / …（原 Kell 状态机，已改名） |
| `thesis` | text ≤ 80 字 | 一句话：为什么是现在、为什么是它。写不出一句话说明想不清楚 |
| `evidence[]` | array | 每条 `{source_id, published_at, summary, url}`。`source_id` 必须来自固定源清单。**空数组也是合法记录**，表示"当时固定源上没有证据" |
| `evidence_strength` | 0–5 | 事前主观打分，必须附一句理由。这是被校准的对象，不是输入信号 |
| `expectation` | object | `{horizon_days, target_excess_pct, benchmark}`，benchmark ∈ {等权组合, 沪深300} |
| `invalidation` | object | `{price, atr_value, atr_multiple}` — 失效位的绝对价格 + 当日 ATR20 + 倍数（默认 2） |
| `r_unit` | object | `{per_share, pct_of_nav}` — 1R = 入场价 − 失效位；占净值百分比 |
| `planned_size_pct` | number | 计划仓位；按 §5 的波动率预算算出 |
| `scoring_rule` | object | 见 §3。**从固定菜单里选，不自由填写** |
| `tracking_days` | int | 出场后继续跟踪多少交易日（默认 20） |
| `counterfactual` | object | 创建当日的等权组合点位、沪深300 点位、该容器价格 |
| `crowding_at_entry` | object | 观测值快照：`{rs_1m_rank, rs_3m_rank, vol_ratio_20, premium_pct, share_chg_20d}` |

### 2.2 每日追加（append-only，历史行永不修改）

| 字段 | 说明 |
|---|---|
| `date` | 交易日 |
| `close` | 当日收盘（后复权） |
| `state` | 当日形态状态 |
| `z` | 延伸度 |
| `rs_1m_rank` | 当日横截面排名 |
| `r_current` | 当前浮动 R 倍数 |
| `mfe` / `mae` | 至今最大有利 / 不利偏移（R 倍数） |
| `stop_now` | 当前止损位（移动止盈上移后的值） |
| `bench_close` | 当日基准点位 |
| `note` | 可选，只记观测，不记解释 |

### 2.3 出场时写入（write-once）

`exit_date` · `exit_price` · `exit_reason` ∈ {失效位, 移动止盈, 论点作废, 跟踪期满, 手动} · `realized_r` · `realized_excess_pct` · `holding_days`

`exit_reason = 手动` 必须写理由，并且这张卡在统计里单独标记——手动干预的比例本身是要被监控的指标。

### 2.4 跟踪期满时写入（write-once）

`post_exit_return_pct`（出场后 N 日走势）· `post_exit_r`（若继续持有会是多少 R）· `final_score`（按 §3 机械计算）· `missed_r`（砍早了多少）

`post_exit_r` 是用来评价**离场规则本身**的，和评价入场信号分开。2026 年那次的教训就在这里：入场没问题，是离场把右尾截断了。

### 2.5 明令禁止

- 不允许事后添加或修改 `evidence[]`
- 不允许修改 `expectation`、`invalidation`、`scoring_rule`、`evidence_strength`
- 不允许删除任何卡片，包括作废的
- 想修正判断，只能**作废旧卡 + 新建卡**，新卡的 `supersedes` 字段引用旧卡 id；两张卡都计入统计

## 3. 评分规则（固定菜单，创建时选定）

出场并跟踪期满后，按创建时锁死的 `expectation` 机械判定，四档：

| 档 | 条件 |
|---|---|
| **达标** | `realized_excess_pct ≥ target_excess_pct` |
| **部分** | `0 < realized_excess_pct < target_excess_pct` |
| **未达** | `realized_excess_pct ≤ 0` 且未触发失效位 |
| **证伪** | 触发失效位出场（`realized_r ≤ −1`） |

另外三个独立标记，不参与上面的分档：

- `stop_quality`：出场后 N 日是否反向走出 ≥ +1R（= 砍早了）
- `trail_quality`：移动止盈是否在 MFE 的 70% 以内出场（= 回吐多少）
- `benchmark_beat`：同期基准是涨是跌（防止牛市里什么都"达标"）

**评分规则一旦锁定，在整个验证周期内对所有卡片一致，不因市场变化而调整。** 理由见 §4。

## 4. 什么变、什么不变（回答"动静结合"）

按变化速率分四层，每层的更新机制完全不同：

**第 0 层 · 宪法，永不改。** 评分规则本身、1R 的定义、锁字段的纪律、作废卡计入分母。**改了尺子就没法跨时间比较**，这一层的稳定性比它的正确性更重要。真要改，等于重新开始计数，新旧记录不可合并统计。

**第 1 层 · 自适应，不需要学。** 这是回答"市场在变怎么办"的主力，而且经常被忽略：**把规则写成相对量，它自己就跟着市场走**。2 倍 ATR 不是一个固定价格——市场波动放大，止损自动变宽、仓位自动变小；横截面排名前 20% 不是一个固定收益率——全市场都跌的时候，前 20% 也可能是负的。凡是用相对量、分位数、波动率单位表达的规则，都不需要"自学习"就已经在适配。**先把能写成相对量的都写成相对量，再谈学习。**

**第 2 层 · 观测，每天更新。** 形态状态、z、排名、量比、溢价、份额变化。它们是被记录的事实，不是参数，没有拟合问题。

**第 3 层 · 校准，按周期、按触发器更新。** 见 §6。唯一允许被数据修改的东西，而且改的不是规则，是**我对自己自信程度的换算表**。

## 5. 仓位（沿用预注册 §5，此处只记卡片相关的）

`planned_size_pct = 单笔风险预算 ÷ (1R ÷ 入场价)`，单笔风险预算默认 0.5% 净值；单容器上限 25%，同时持仓上限 8，总风险上限 4%。

## 6. 验证与适配（回答"怎么知道有效、怎么跟上市场"）

### 6.1 主检验：校准，不是归因

**不学"哪条信息有用"，只学"我的自信有多准"。** 前者必然是事后选择（二十条信息里挑出事后对得上的那几条），后者的分桶在事前就定死了。

做法：把所有已结卡片按 `evidence_strength` 分桶（0–1 / 2–3 / 4–5），看每桶的达标率和平均 R。

- **有区分度** = 高分桶的达标率显著高于低分桶 → 证据层带信息，可以考虑让它进入仓位决策
- **无区分度** = 各桶拉平 → 证据层不带信息，**直接废弃这一维，不做调参抢救**
- **反向** = 高分桶更差 → 我的主观判断是负信息，同样废弃

每桶需要 ≥ 30 条才看，所以最早的结论在 12–18 个月之后。

### 6.2 必须的对照

每张卡都要对 `counterfactual` 打分：同期等权组合、同期沪深300、以及**同期随机挑一个容器**的表现。
没有这层对照，牛市里所有卡片都"达标"，看板会变成一个自我恭维的机器。

### 6.3 允许的适配：只有一件

`evidence_strength` 的**换算表**可以更新。比如积累到 50 条之后发现"我打 4 分的，实际达标率只有 35%"，那就把 4 分记为 35% 而不是改变打分方式。这是单参数重标定，不是重新学习。

**不允许的适配**：改阈值、改 ATR 倍数、改排名门槛、加新变量、给信息源加权重。这些都是在用结果拟合规则。

### 6.4 审查的触发器（事先写死，不是想起来才做）

定期：每 12 个月一次全面审查。
触发式，任一条满足立即审查：

- 连续 20 张已结卡片的平均 R ≤ −0.2
- 校准连续 3 个季度反向（高分桶差于低分桶）
- 手动出场的比例超过 30%（说明规则已经不被信任了）
- 容器池发生结构性变化（主题 ETF 清盘、新主题出现且成交额进前十）

**审查的结论只有三种：继续、停止、重开新版本（换宪法，重新计数）。没有"微调"这个选项。**

## 7. 需要人的部分 vs 自动的部分

| 环节 | 能否自动 |
|---|---|
| 拉数据、算状态/z/排名/R、更新每日行、渲染面板 | **完全自动**，每日定时任务 |
| 触发候选卡（形态突破 / 恐慌下轨） | **完全自动** |
| 把新闻事件映射到容器、起草 thesis、给 evidence_strength | **半自动**：可由定时任务起草，但必须人确认后才锁卡 |
| 出场、机械打分、跟踪期统计 | **完全自动** |
| §6.4 的审查结论 | **必须人做**。这是唯一有真实后果的决定，不交给自动化 |

也就是说：日常运转不需要我，起卡需要一次确认，一年一次的审查需要一次真正的讨论。

## 8. 未定，需要你拍板

1. `evidence_strength` 由谁给：你、我起草你确认、还是双盲各给一次再比较？第三种最能检验"主观判断是否带信息"，但每天多一步。
2. 跟踪期默认 20 个交易日够不够，还是分 trigger_type 给不同值。
3. 事件驱动型卡片要不要单独的失效位定义（事件类的失效往往是"事件本身被证伪"，不是价格）。
4. 面板上"未来卡片"（潜在机会）要不要也进台账。倾向要——它们是"看到了但没进"的样本，正是最容易被遗忘的那部分分母。
